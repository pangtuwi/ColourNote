# ColourNote — Unit Test Documentation

## Overview

The `ColourNoteXCTests` target contains a unit test suite using the **Swift Testing** framework
(`import Testing`, `@Test`, `#expect`). All 40 tests pass on a clean simulator.

The test target is configured with `BUNDLE_LOADER = $(TEST_HOST)`, meaning the test bundle runs
inside the host app process. All `internal` app types are therefore accessible at runtime, but
`@testable import ColourNote` is still required in every file for the Swift compiler to resolve
those types at compile time.

---

## Framework & Conventions

| Item | Detail |
|------|--------|
| Framework | Swift Testing (not XCTest) |
| Import | `@testable import ColourNote` in every test/helper file |
| Test functions | `@Test func testName()` (not `func testName()`) |
| Assertions | `#expect(condition)` / `Issue.record(...)` |
| Async callbacks | Bridged with `await withCheckedContinuation { ... }` |
| Parallelism | Tests run in parallel by default; `@Suite(.serialized)` used where global state (Keychain) is shared |

## Dependency Injection Architecture

The sync layer uses a `NetworkManaging` protocol (defined in `NetworkManager.swift`) to enable
offline testing without hitting real network endpoints.

### Protocol: `NetworkManaging`

Declared above `class NetworkManager` in `Shared/CloudSync/NetworkManager.swift`. Covers all
HTTP verbs, token management, and `isAuthenticated`.

### DI pattern applied to three classes

Each of the following classes was refactored from a hard-coded `NetworkManager.shared` property
to accept a `NetworkManaging` via an initialiser:

| Class | File |
|-------|------|
| `NetworkManager` | `Shared/CloudSync/NetworkManager.swift` — adds `internal init(session: URLSession)` for URLProtocol injection |
| `NoteSyncService` | `Shared/CloudSync/NoteSyncService.swift` |
| `CategorySyncService` | `Shared/CloudSync/CategorySyncService.swift` |
| `AuthManager` | `Shared/CloudSync/AuthManager.swift` |

Pattern used in each service:

```swift
let networkManager: NetworkManaging          // internal — accessible in tests

init(networkManager: NetworkManaging) {      // designated — used by tests
    self.networkManager = networkManager
}

private convenience init() {                 // used by .shared singleton only
    self.init(networkManager: NetworkManager.shared)
}
```

The singleton path is entirely unaffected; production callers continue to use `.shared`.

## Test Helpers (`ColourNoteXCTests/Helpers/`)

### `MockURLProtocol.swift`

A `URLProtocol` subclass that intercepts every `URLSession` request. Used in
`NetworkManagerTests` to test HTTP request construction against a real
`NetworkManager(session:)` instance (not the singleton).

```swift
// Wire up in each test:
let config = URLSessionConfiguration.ephemeral
config.protocolClasses = [MockURLProtocol.self]
let sut = NetworkManager(session: URLSession(configuration: config))

MockURLProtocol.requestHandler = { request in
    return (HTTPURLResponse(...), data)
}
```

### `MockNetworkManager.swift`

Conforms to `NetworkManaging`. Fully offline — completion handlers are called synchronously.
Used by `AuthManagerTests`, `NoteSyncServiceTests`, and `CategorySyncServiceTests`.

Key properties:

| Property | Purpose |
|----------|---------|
| `calledEndpoints: [String]` | Records every endpoint string passed to any method |
| `lastBody: (any Encodable)?` | Records the last request body |
| `stubbedGETData` / `stubbedGETError` | Return value for `get(...)` calls |
| `stubbedPOSTData` / `stubbedPOSTError` | Return value for `post(...)` calls |
| `stubbedPUTData` / `stubbedPUTError` | Return value for `put(...)` calls |
| `stubbedDELETEError` | Return value for `delete(...)` / `requestNoResponse(...)` calls |
| `stubbedToken` / `stubbedIsAuthenticated` | Token and auth state stubs |

### `TestFixtures.swift`

Static factory methods returning pre-built instances for use across test suites:

| Method | Returns |
|--------|---------|
| `makeNote(...)` | `Note` with sensible defaults |
| `makeCategory(...)` | `ColourNote.Category` with sensible defaults |
| `makeCloudNote(...)` | `CloudNote` |
| `makeCloudCategory(...)` | `CloudCategory` |
| `makeAuthResponse(token:)` | `AuthResponse` |
| `encode<T: Encodable>(_:)` | `Data` — JSON-encodes a value |
| `httpResponse(status:url:headers:)` | `HTTPURLResponse` |

## Out of Scope

The following are explicitly excluded from unit testing because they use a singleton with a
hard-coded SQLite path that cannot be injected:

- `NoteRecords` / `CategoryRecords` — database manager singletons
- Full sync flows in `SyncEngine` — these require a live database

Integration-level tests (requiring the simulator DB) are noted inline where applicable.

## Running the Tests

- **Full suite**: `Cmd+U` in Xcode with the `ColourNoteXCTests` scheme selected
- **Single suite**: Click the diamond next to any `struct` or `@Test` in the gutter
- **Requirements**: iOS Simulator (Keychain is available; device not required)
